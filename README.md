# Surveil Technologies — Website

Marketing website for Surveil Technologies, a veteran-owned commercial cabling and security technology company based in League City, Texas.

- **Pages:** Home, Services, Builders & Commercial Projects, About, Contact / Request a Site Walk, 404
- **Front end:** plain HTML, CSS, and a small JavaScript file, generated by a zero-dependency Node build script. Nothing to `npm install`.
- **Contact form backend:** AWS Lambda + Amazon SES behind an API Gateway HTTP API, defined in `backend/template.yaml`.
- **Hosting:** AWS Amplify Hosting (recommended) or S3 + CloudFront.

See **[LAUNCH-CHECKLIST.md](LAUNCH-CHECKLIST.md)** for what must be filled in before going live.

## 1. Run it locally

Requirements: [Node.js](https://nodejs.org) 20 or newer (the current LTS is fine).

```bash
npm run dev
```

Open http://localhost:4321. The site rebuilds when you save a file in `src/`; refresh the browser to see changes.

In local development, the contact form posts to a **test endpoint that only exists on your machine**. It checks the fields like the real backend and prints the submission in your terminal; no email is sent. To see the error message, put `#fail` in the project description.

Other commands:

| Command | What it does |
| --- | --- |
| `npm run build` | Production build into `dist/` (clean URLs such as `/services/`) |
| `npm run build:preview` | Single-folder build into `dist-preview/` that also opens from disk |
| `npm run check` | Lists missing launch details; fails if required ones are missing |
| `npm test` | Runs the contact form backend tests |

## 2. Edit content

Almost everything lives in **`src/content/site.js`**:

| What | Where in `site.js` |
| --- | --- |
| Phone, email, website address | `business.phone`, `business.email`, `business.siteUrl` |
| Logo | `business.logo` (leave `null` to use the text wordmark) |
| Services (titles, descriptions, bullet lists) | `services` |
| "Who we work with" cards | `customerTypes` |
| 4-step process | `processSteps` |
| Contact form timeline choices | `form.timelineOptions` |
| Page titles and search descriptions | `seo` |
| Photos | `photos` |

Examples:

```js
phone: { display: '(281) 555-0100', tel: '+12815550100' },
email: 'info@yourdomain.com',
siteUrl: 'https://www.yourdomain.com',
```

Anything left as `null` shows as a yellow **[placeholder]** on the site (phone, email) or quietly falls back (logo → text wordmark, photos → illustrations). Once a phone number is set, a **Call** button appears in the mobile contact bar automatically.

**Page wording** that isn't in `site.js` (hero text, About story, Builders page sections) is in `src/pages/*.js`. Each file is mostly plain HTML inside a template string, so you can edit the text directly.

**Colors and fonts** are defined as variables at the top of `src/styles/main.css`.

### Adding photos

1. Export each photo as `.webp` or `.jpg`, about **1600 px wide**, ideally under **250 KB** (free tool: [Squoosh](https://squoosh.app)).
2. Put it in `src/assets/images/` (create the folder).
3. In `site.js`, set the matching slot, for example:
   ```js
   hero: { src: 'images/rack-install.webp', width: 1600, height: 1200, alt: 'Network rack with labeled patch cables at a League City office' },
   ```

Use your own installation photos, or licensed stock photos that are not presented as your projects. Write `alt` text that describes what's in the photo.

### Adding a logo

Put the file (SVG preferred) in `src/assets/images/` and set:

```js
logo: { src: 'images/logo.svg', width: 220, height: 40 },
```

## 3. Deploy the contact form backend (AWS)

The form needs a small backend to send email. Nothing secret is in the website code: the page only knows a public URL, and the backend uses its own AWS IAM role to send mail.

```
Browser ──POST JSON──▶ API Gateway (HTTP API, throttled, CORS limited to your domain)
                            │
                            ▼
                       Lambda (validates, filters spam) ──▶ Amazon SES ──▶ your inbox
```

The website shows **"Thank you. Your request was received."** only when the backend answers `{ "ok": true }`, which happens only after SES accepts the email. Otherwise the visitor sees "Your message was not sent" and their entries stay in the form.

### Prerequisites

- An AWS account, the [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html), and the [AWS SAM CLI](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/install-sam-cli.html), signed in with `aws configure` or `aws sso login`.
- Your domain (e.g. `yourdomain.com`).

### Step A: Set up Amazon SES

1. In the AWS console, open **Amazon SES** in the Region you'll deploy to (for example `us-east-1` or `us-east-2`).
2. **Identities → Create identity → Domain**, enter your domain, and add the DNS records it gives you (automatic if your DNS is in Route 53). This lets you send from an address like `website@yourdomain.com`.
3. New SES accounts start in the **sandbox**, where mail can only go to verified addresses. Either verify the inbox that receives inquiries (**Create identity → Email address**), or request **production access** from the SES account dashboard. Verifying your receiving address is enough for a contact form that only emails you.

### Step B: Deploy

```bash
cd backend
sam build
sam deploy --guided
```

Answer the prompts:

| Prompt | Example |
| --- | --- |
| Stack name | `surveil-contact-form` |
| AWS Region | the Region where you set up SES |
| AllowedOrigins | `https://www.yourdomain.com,https://yourdomain.com` |
| ToEmail | the inbox that should receive inquiries |
| FromEmail | `website@yourdomain.com` (on your verified SES domain) |

When it finishes, copy the **ContactEndpoint** output. It looks like `https://abc123.execute-api.us-east-1.amazonaws.com/contact`.

For testing before your domain is live, you can temporarily include your Amplify preview URL (for example `https://main.d1234.amplifyapp.com`) in `AllowedOrigins`, then redeploy with the final list.

### Step C: Test it

```bash
curl -i -X POST "$ENDPOINT" \
  -H "Content-Type: application/json" \
  -H "Origin: https://www.yourdomain.com" \
  -d '{"name":"Test","company":"Test Co","email":"you@yourdomain.com","location":"League City","service":"Structured Network Cabling","timeline":"Within the next month","description":"Testing the website contact form."}'
```

A `200` with `{"ok":true}` and an email in your inbox means it works. Errors are logged in **CloudWatch Logs** under `/aws/lambda/<function name>`.

What's built in: server-side validation, a hidden spam-trap field, a 20 KB request limit, API throttling (2 requests/second, burst 10), CORS and origin checks limited to your domain, and an IAM policy that only allows sending from your `FromEmail` address. Replies go straight to the visitor because their address is set as Reply-To.

## 4. Deploy the website

### Option 1 (recommended): AWS Amplify Hosting

1. Put this project in a Git repository (GitHub, GitLab, Bitbucket, or CodeCommit).
2. In the AWS console, open **AWS Amplify → Create new app → Host web app**, and connect the repository. Amplify picks up `amplify.yml` automatically.
3. Under **Hosting → Environment variables**, add `FORM_ENDPOINT` = the ContactEndpoint URL from step 3B. Redeploy.
4. Under **Hosting → Rewrites and redirects**, add: source `/<*>`, target `/404.html`, type **404 (Rewrite)**.
5. Under **Hosting → Custom domains**, add your domain. Amplify issues the HTTPS certificate.
6. Security headers: `customHttp.yml` is read from the repo root; if your Amplify app doesn't pick it up, paste its contents into **Hosting → Custom headers**.

Every push to your main branch rebuilds and redeploys the site.

No Git? You can also run `FORM_ENDPOINT=https://… npm run build`, zip the **contents** of `dist/`, and use Amplify's **Deploy without Git** upload.

### Option 2: S3 + CloudFront

1. Create a private S3 bucket (Block Public Access on).
2. Create a CloudFront distribution with the bucket as origin using **Origin Access Control**, and set **Default root object** to `index.html`.
3. Add a **CloudFront Function** from `deploy/cloudfront-index-rewrite.js` on *Viewer request* so `/services/` serves `services/index.html`.
4. Add a custom error response: HTTP 403 and 404 → `/404.html`, response code 404.
5. Request an ACM certificate in **us-east-1** for your domain, attach it to the distribution, and point DNS (Route 53 alias) at CloudFront.
6. Build and upload:
   ```bash
   FORM_ENDPOINT=https://abc123.execute-api.us-east-1.amazonaws.com/contact npm run build
   aws s3 sync dist/ s3://YOUR-BUCKET --delete
   aws cloudfront create-invalidation --distribution-id YOUR-DIST-ID --paths "/*"
   ```
7. Optional: add a CloudFront **Response headers policy** with the same headers as `customHttp.yml`.

## 5. Project structure

```
src/
  content/site.js        ← business details, services, SEO (edit here first)
  pages/                 ← one file per page
  components/            ← header/footer, buttons, cards, form, illustrations
  styles/main.css        ← all styles and design tokens
  scripts/main.js        ← mobile menu and contact form behavior
  assets/                ← fonts (self-hosted, OFL licensed), favicon, your images
scripts/
  build.mjs              ← static site build
  dev.mjs                ← local server with test form endpoint
backend/
  template.yaml          ← AWS SAM: API Gateway + Lambda + SES permissions
  src/contact/           ← Lambda code (handler.mjs, validate.mjs, index.mjs)
  test/                  ← backend tests (npm test)
deploy/
  cloudfront-index-rewrite.js
amplify.yml, customHttp.yml
```

## Accessibility and SEO notes

- Semantic headings (one `h1` per page, no skipped levels), skip link, visible focus styles, keyboard-operable menu (Esc closes it).
- Form fields have visible labels, hints and errors linked with `aria-describedby`, an error summary that receives focus, and a live status region.
- Text and UI colors meet WCAG 2.1 AA contrast. Motion is limited to color transitions and respects reduced-motion settings.
- Each page has its own title and meta description; canonical URLs, `sitemap.xml`, and `LocalBusiness` structured data are generated once `business.siteUrl` is set. No street address is published.
